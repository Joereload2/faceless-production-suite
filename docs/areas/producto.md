## Trabajo

- Guardar las puertas humanas.
- Mover el tablero de etapas. No aceptar etapas a medias.
- Decidir recortes si duele el tiempo (orden en el roadmap).
- Escribir el done en lenguaje de usuario: sale un wav, sale el master, no se refactoreo el store.

## Reglas

1. v1 = primer `master_16x9.mp4` local. Todo lo demas es extra.
2. Auto-publish y auto-delete son etapa 10 / v2.
3. Un canal, un tono, una voz Piper. No marketplace de voces.
4. SEO no publica.
5. Si una feature exige un segundo orquestador, se rechaza.
6. Copy de UI en espanol. Errores visibles = frase humana + codigo.

## Artefactos que el PM mantiene

- Tablero de etapas (issue o proyecto GitHub).
- Lista de canales piloto (uno en v1).
- Fixture de guion de 80–120 palabras para E3 y E7.
